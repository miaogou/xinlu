Linux 驱动学习的第二个项目，本质是对 `gpio_key` 的升级版，从该项目的名称就可以看出，其就是将设备树加入我的 `gpio_key` 这个小项目中。

既然已知 `gpio18` 为按键的信息传递 `gpio` 口，那我为什么不直接将其写死呢？反倒方便一点～～

通过后续的了解得知，设备树的编译与驱动应用程序的编译是分别进行的，也就是说：

1. 当我的硬件条件发生变化时，可以在不改变设备树的节点名的情况下，直接对硬件描述进行更改，这样就不需要重新更改并编译我们的驱动程序，比较方便。
2. 对硬件采取设备树这种描述方式可以在我们驱动一个传感器时，快速定义其需要的一系列硬件，实现统一申请，统一调用。

## 本项目就是引用了设备树

1. 在 `gpio_key_dts` 这个文件中的 `dts` 子路径下保存着我们更改的完整设备树，我对改进的地方进行了详细注释，方便理解。
2. 更改完设备树之后我们需要在我们的驱动程序中对其进行调用操作，主要集中在 `gpio_key_dts` 的第 79 - 154 行，也就是驱动五大块中的第三块。
